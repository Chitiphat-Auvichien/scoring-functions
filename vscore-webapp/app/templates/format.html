The .vsc format, v1.0

One self-contained file carrying everything the scorer needs and nothing it doesn't. A few kB where a Gaussian log is megabytes, because the parts that dominate a log — SCF iterations, the Hessian, integrals — are never read.

Full example

#VSCORE 1.0
#TITLE   HOCl  MP2/3-21G
#SOURCE  HOCl.log + HOCl.com

[GEOMETRY] Angstrom
    1  O        0.038069       1.197522       0.000000
    2  H       -0.951724       1.378354       0.000000
    3  Cl       0.038069      -0.644619       0.000000

[CONNECTIVITY]
    1  2  3
    2
    3

[MODES] 3
  mode 1   freq=667.6406   mu=17.7040   k=4.9258   irrep=A'
    1      0.00088      0.85015     -0.00000
    2     -0.16190      0.30478     -0.00000
    3      0.00426     -0.39765      0.00000
  mode 2   freq=1256.0043  irrep=A'
    ...

Rules

  • Header. #VSCORE 1.0 first. #TITLE and #SOURCE optional. Any # line is a comment; trailing # comments and blank lines are ignored everywhere.
  • [GEOMETRY] — one atom per line, index element x y z. The leading index is optional. The element may be a symbol (Cl, case-insensitive) or an atomic number (17). Coordinates in Ångström.
  • [CONNECTIVITY] — the Gaussian .com idiom: centre partner [order] partner [order] …, one line per atom. Bond orders are accepted and ignored — they play no part in the V-score. Bonds are symmetric and de-duplicated, so listing each once is enough. Required.
  • [MODES] N — N optional; if given it must match. Each mode opens with mode <n> plus optional freq= (or eigen= for an EMIT mode), mu=, k=, irrep=, followed by one dx dy dz row per atom (optional leading index).

EMIT modes

Use eigen= instead of freq= on a mode header to mark it as an EMIT mode rather than a Gaussian normal mode — eigenvalues can be negative, unlike a vibrational frequency, and the two are scored differently. EMIT eigenvectors already live in the principal-axis frame, so the pipeline rotates only the molecule into that frame, not the mode vectors a second time (rotating them again would silently invert the T/R scores). Getting this tag right therefore matters more than any other piece of mode metadata, all of which the scorer otherwise ignores. See examples/C6H6_EMIT.vsc. 

[MODES] 36
  mode 1   eigen=-23.7514
    1      0.00000      0.00000      0.00000
    ...

Optional fields, in full

Only four things are load-bearing: the element of each atom, its coordinates, the connectivity, and the displacement rows. Everything below is optional and every combination is accepted — each row here is exercised by the test suite.

Mode metadata

Written after mode <n>, in any order, space separated. Keys are case-insensitive (FREQ= works) and unrecognised key=value pairs are ignored, so extra annotation is harmless. The scorer reads none of them — they are row metadata that rides through to the table and the CSV.

freq= Harmonic frequency in cm⁻¹. Shown in the ν column. Absent means absent, not zero: the row shows a dash rather than an invented 0.00.
eigen= Marks the mode as EMIT. Carries an EMIT eigenvalue rather than a wavenumber, so the column re-labels itself eigenvalue instead of claiming cm⁻¹. It also changes how the mode is treated: EMIT eigenvectors already live in the principal-axis frame, so the molecule is rotated into that frame and the vectors are left alone. Rotating them as well applies the transform twice — on benzene that mislabels 9 of 36 modes. Use it whenever the geometry is in one frame and the eigenvectors in another. Mutually exclusive with freq=; if both appear, eigen= wins as the more specific tag.
mu=Reduced mass in AMU. Output only.
k=Force constant in mDyne/Å. Output only.
irrep= Irreducible representation, free text (A', B2U…). Output only.
  mode 1   freq=667.6406   mu=17.7040   k=4.9258   irrep=A'   ← all of them
  mode 2   freq=1256.0043                                      ← one of them
  mode 3   eigen=-23.7514                                      ← an EMIT mode
  mode 4                                                       ← none at all

File and block syntax

#VSCORE 1.0 Version marker. Parsed as a comment, so a file without it still reads — but write it: it is the only thing identifying the format.
#TITLE / #SOURCE Free text. The title names the result page; the source is provenance for whoever opens the file later.
# comments Anywhere, whole-line or trailing. Blank lines ignored throughout.
[GEOMETRY] unit The Angstrom after the tag is decorative; Å is assumed either way.
atom index The leading serial in a [GEOMETRY] row may be omitted, and likewise on displacement rows.
element Symbol (Cl, any case) or atomic number (17).
bond orders Accepted and ignored in [CONNECTIVITY], so a block pasted straight from a .com deck works. Bonds are symmetric and de-duplicated — listing each once is enough.
[MODES] N The count is optional. Given, it must match the number of modes found, which catches a truncated paste.

3N or 3N−6? Detected, not declared

A .vsc can hold either the vibrations alone or the complete set including translation and rotation, and the upload form asks which. The choice decides whether the six ideal T/R reference modes are constructed and added to the pool.

3N−6
vibrations only		 The usual case, and what a Gaussian frequency job gives you — T/R are projected out at a stationary point. The six ideal references are constructed and prepended so they fill the external slots. Without them the assignment fills those slots from your vibrations instead: on H2O that labelled a 0.997 O–H stretch Tx*. Fewer than 3N−6 modes is fine — score a single mode if you like. 3N−5 for a linear molecule.
3N
T/R included		 Nothing is constructed. The algorithm identifies the six T/R modes among the ones you supplied, using the same external-slot assignment it always uses. Must be exactly 3N.

3N works cleanly when the supplied T/R modes are motions about the principal axes of inertia. If they are rotations about some other axes — which is what an unprojected Hessian diagonalisation gives — each becomes a mixture of Rx/Ry/Rz once the molecule is rotated into its principal frame. No single slot score is then high enough to win, so a real vibration can take the slot and a genuine rotation falls through to B. The app detects this: any external assignment that fails the purity gate is reported with a starred label and a warning on the results page. examples/HCOOH_3N.vsc is a clean 3N set to compare against.

Why connectivity is mandatory

s[VS] is a weighted sum over bonds. With an empty bond list it evaluates to exactly 0.000 for every mode — and since 0.000 ≤ τB, every mode would then be labelled B. That failure produces a complete, plausible, entirely wrong table with no error anywhere. So a file without [CONNECTIVITY] is rejected rather than scored, and bonds are never inferred from interatomic distances.

Precision

Write displacements at full precision — Gaussian freq=hpmodes, five decimal places. Standard two-decimal output survives the labels (V_S moves by ≤0.03, against a stretch/bend gap of 0.73) but shifts individual T-scores by up to 0.31 on a [−1, 1] scale, because Tscore() unit-normalises each atom's displacement before summing, so an atom printed as 0.00 0.00 0.00 is either masked to zero or promoted to a full unit vector on rounding noise. The app detects low-precision input and warns.

Producing one

  • Score any .log + .com pair and click .vsc on the results page.
  • In bulk: python make_vsc.py mol.log mol.com -o mol.vsc, or python make_vsc.py --batch logs/ gjf/ -o out/.

The geometry written is the original frame the data arrived in, not the principal-axis frame the scores are computed in. That matters: the alignment step is not idempotent — its sign-fix heuristic negates the rotation when the heaviest atom's projected coordinates sum negative, so re-aligning an already-aligned geometry can flip axes and invert the T and R scores. Storing the original frame makes the round trip exact, verified across all 69 reference molecules.
